# Contributing to Awesome Blockchains

Thanks for helping improve Awesome Blockchains. This repository curates educational blockchain resources, practical build-your-own blockchain material, crypto hash references, Git-related distributed database resources, and small example implementations in several programming languages.

## What Belongs Here

Good contributions usually fit one of these categories:

- Educational articles, books, talks, or references about blockchains as distributed databases.
- Practical tutorials for building simple blockchain or Merkle tree examples.
- Small, readable code samples that match the repository's learning-focused style.
- Crypto hash or content-addressed data resources that support the existing sections.
- Related awesome lists that are clearly useful to readers of this collection.

Keep additions educational and neutral. Avoid promotional copy, referral links, price speculation, trading advice, and resources that are only about launching or marketing a token.

## Entry Style

Use the existing README style for links:

```markdown
- [Resource Name](https://example.com/) - Short factual description.
```

For code examples, keep the sample small enough to read, prefer standard tooling for the language, and add a short note when a command or dependency is required.

## Before Opening a Pull Request

1. Search the README and related files to avoid duplicate resources.
2. Check that each link works and points to the canonical project, article, or documentation.
3. Put each resource in the most specific existing section.
4. Keep descriptions concise, factual, and consistent with nearby entries.
5. Run any relevant example or syntax check when changing code samples.

## Pull Request Guidelines

- Keep each pull request focused on one topic or a small related set of entries.
- Explain why the resource belongs in this collection.
- Mention whether the resource is maintained, archived, historical, or experimental.
- Keep unrelated formatting-only changes separate from content changes.
- If you add a code sample, include enough context for a reader to run or inspect it.

Maintainers may ask for a shorter description, a different section, or additional context before merging.
